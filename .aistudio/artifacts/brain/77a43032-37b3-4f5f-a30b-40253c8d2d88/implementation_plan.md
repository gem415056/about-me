# TXT 및 HTML 파일 첨부 및 원문 지속 전송 구현 계획

명리학과 심리학 입력창의 '+' 첨부 버튼을 확장하여 이미지뿐만 아니라 `.txt` 및 `.html` 문서 파일을 첨부할 수 있도록 하고, 첨부된 문서의 원문 내용을 일체의 요약이나 왜곡 없이 100% 온전히 읽어 세션 내에서 사용자가 삭제하기 전까지 매 대화 턴마다 지속적으로 페이로드에 실어 전송합니다.

## User Review & Critical Decisions

> [!IMPORTANT]
> 사용자가 요청하신 "TXT와 HTML 파일의 온전한 원문 전송" 및 세션 지속 유지에 맞추어 설계를 명확히 확정했습니다.

- **확정된 결정 1 (원문 무결성 100% 전달)**:
  - 파일 파싱이나 인위적인 요약·변형 없이, `FileReader.readAsText(file, 'utf-8')`를 통해 파일에 적힌 텍스트와 태그를 있는 그대로 온전히 추출합니다.
  - Gemini API 호출 시 `[첨부 파일: 파일명]` 헤더와 함께 원문 텍스트 전체를 `parts.text`로 투명하게 포함합니다.
- **확정된 결정 2 (세션 내 영구·지속 전송)**:
  - 사진 및 만세력과 동일하게, 사용자가 칩 우측의 `✕` 버튼을 눌러 직접 삭제하기 전까지 현재 세션(IndexedDB)에 영구 보존됩니다.
  - 대화가 여러 턴 오가는 동안에도 매 턴마다 첨부 파일 원문이 페이로드에 계속 실려 모델이 전체 문서 맥락을 유지합니다.
- **확정된 결정 3 (간결한 첨부 칩 디자인)**:
  - 사용자가 선택하신 대로 복잡한 미리보기 없이, 입력창 상단에 **'문서 아이콘 + 파일명 + ✕ 삭제 버튼'**의 직관적이고 미니멀한 칩으로 렌더링됩니다.
- **확정된 결정 4 (인위적 기본 문구 완전 배제)**:
  - 시스템 임의의 기본 보일러플레이트 문구 주입을 완전히 배제하고, 사용자가 입력한 순수 질문 텍스트와 첨부 파일 내용만 정직하게 전송합니다. 빈 텍스트 상태에서는 전송이 차단되고 입력창에 포커스를 둡니다.

## 1. Overview & Core Concept

- **What It Does**:
  - 명리학 및 심리학 입력창 좌측의 '+' 파일 첨부 버튼 클릭 시 이미지뿐 아니라 `.txt`, `.html` 파일도 자유롭게 선택 가능.
  - 첨부된 문서 내용은 인위적 필터링 없이 원문 그대로 세션에 누적되고, 대화 턴마다 모델에 전달되어 사용자가 방대한 텍스트나 HTML 구조를 바탕으로 상담·분석을 받을 수 있도록 지원.
- **Target Audience / Persona**:
  - 사주 명식 텍스트 기록, 상담 기록, 성격 분석지 HTML, 외부 문서 등을 AI에게 온전히 제공하여 심층적인 분석과 대화를 나누고자 하는 사용자.
- **Key Value**:
  - 번거롭게 텍스트를 복사-붙여넣기하여 긴 입력창에 밀어 넣을 필요 없이, 파일 첨부 한 번으로 세션 내내 원문 데이터가 지속적으로 유지·반영되는 쾌적한 UX.

---

## 2. User Experience & Visual Design

- **Key User Flows**:
  1. **파일 선택**:
     - 사용자가 입력창 좌측의 '+' 버튼을 클릭하면 파일 선택 창이 열리며, 이미지뿐 아니라 `txt`, `html` 파일도 선택 가능합니다.
  2. **칩 표시**:
     - 선택 즉시 입력창 상단 영역에 파일 칩이 나타납니다.
     - 이미지 파일: 썸네일 + 파일명 + ✕ 버튼.
     - TXT/HTML 문서 파일: 깔끔한 문서 아이콘 + 파일명 + ✕ 버튼.
  3. **대화 전송**:
     - 질문 텍스트를 입력하고 전송하면, 사용자의 질문 텍스트와 함께 첨부된 TXT/HTML의 원문 전체가 Gemini API 페이로드에 실립니다.
  4. **지속성 및 삭제**:
     - 다음 질문을 할 때도 첨부된 파일은 그대로 유지되어 페이로드에 계속 실립니다.
     - 사용자가 칩 우측의 ✕ 버튼을 클릭하면 세션에서 즉시 제거되고 이후 대화 페이로드에서도 제외됩니다.
- **Visual Identity & Theme**:
  - 모바일 및 데스크톱 환경 모두에서 세련된 Tailwind UI 스타일 준수.
  - 문서 칩은 텍스트 줄바꿈 없이 파일명이 길 경우 우측 말줄임표(`truncate`) 처리되고 ✕ 버튼 타깃 영역(최소 44px 터치 영역 확보)을 갖춥니다.

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: '파싱' 대신 '원문 100% 무손실 읽기' 채택**
  - *Chosen Approach*: `FileReader.readAsText(file, 'utf-8')`를 사용하여 파일에 작성된 문자 그대로를 변형 없이 가져와 페이로드 블록에 주입.
  - *Why*: 사용자가 의도한 데이터(코드, 태그, 줄바꿈, 텍스트)를 단 1글자의 누락이나 임의 재가공 없이 모델에 온전히 전달하기 위함.
- **Decision 2: 통합 첨부 관리 (`AttachmentManager` 확장)**
  - *Chosen Approach*: 기존 `attachedPhotos` 체계를 이미지와 문서를 함께 관리할 수 있는 구조(`attachedFiles`)로 확장하여, 세션 DB 동기화와 UI 칩 렌더링, 페이로드 빌더를 일원화.
  - *Why*: 이미지와 문서가 동일하게 세션 지속성 및 삭제(✕) 메커니즘을 공유하므로 코드 안정성과 유지보수성이 극대화됨.

## 4. Technical Architecture & Data Strategy

### Architecture & Component Diagram

```
┌────────────────────────────────────────────────────────┐
│           입력창 좌측 '+' 파일 첨부 버튼              │
│       (accept="image/*, .txt, .html, text/plain")      │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│                   AttachmentManager                    │
│  - 이미지: readAsDataURL -> { type: 'image', data }    │
│  - TXT/HTML: readAsText  -> { type: 'doc', content }  │
│  - UI: 입력창 상단에 미니멀 칩 (아이콘 + 파일명 + ✕)   │
│  - 세션 동기화: chat_sessions.attachedFiles 영구 보관  │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│                 AIEngine.buildContents                 │
│  - 이미지: inlineData (MIME 타입 + base64)             │
│  - 문서: parts.push({ text: `[첨부: 파일명]\n원문` })  │
│  - 사용자 순수 질문 text 함께 묶어 전송                │
│  - 세션 내 매 턴 지속 반영 (사용자 ✕ 삭제 전까지)     │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│             /api/gemini (Gemini 2.5 Flash)             │
│  - 시스템 프롬프트(실시간 디스크 파일) + 온전한 페이로드│
└────────────────────────────────────────────────────────┘
```

### Component & State Mapping

1. **`index.html` 파일 인풋 확장**:
   - `id="file-input-psychology" accept="image/*,.txt,.html,text/plain,text/html"`
   - `id="file-input-saju" accept="image/*,.txt,.html,text/plain,text/html"`
2. **`AttachmentManager` 확장 (`js/app.js`)**:
   - `addFile(category, file)`: 확장자 및 MIME 확인. 이미지인 경우 Base64 DataURL로 변환, `.txt`/`.html`인 경우 UTF-8 원문 텍스트로 읽어 보관.
   - `render(category)`: 파일 타입이 문서인 경우 Lucide 파일 아이콘 SVG + 파일명 + ✕ 버튼으로 칩 생성.
   - `syncToSession(category)` 및 `loadForSession(category, session)`: 세션 로드 시 이미지 및 문서 복원.
3. **`AIEngine.buildContents` 연동 (`js/app.js`)**:
   - 첨부 목록 중 이미지는 `inlineData`로, 문서는 온전한 원문 텍스트 파트(`text: [첨부 파일: ${fileName}]\n${textContent}`)로 주입.
   - 사용자가 작성한 순수 질문 텍스트와 함께 패키징되어 매 턴 지속 전달.
